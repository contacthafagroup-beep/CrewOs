# CrewOS Architecture

## System shape

```
Browser ── Next.js (App Router, RSC) ── PostgreSQL (Prisma)
                │              └── AI Router ── OpenAI / Anthropic / Gemini / Ollama (plain fetch)
                ├── Stripe SDK ── Stripe (Checkout, Portal, Webhooks)
                └── Email adapter ── Resend (or console)
Worker (separate process or cron) ── same DB, same engine
```

Single Next.js app. No microservices. The only stateful infra is Postgres, which is what makes free-tier deployment possible.

## Agent runtime (`src/lib/engine.ts`)

- **AgentDefinition** (id, inputs, steps, tier, `run(ctx, input)`) — declared in `src/lib/agents/*`.
- `startAgentRun()`: validates input → enforces **plan run-limits** (calendar-month count) → creates `AgentRun` → executes inline (`WORKER_INLINE=true`, default in dev) or enqueues a durable `Job`.
- `executeRun()`: loads the run, builds a `RunCtx` whose two capabilities are injected:
  - `ctx.step(id, status)` — writes step progress into `AgentRun.output` (live UI).
  - `ctx.ai(tier, opts)` — routes to the AI provider, **records a `UsageEvent`** (tokens + est. cost) per call.
- Failures set `AgentRun.status=FAILED` with the error surfaced in UI + a notification. Metering persists even for failed runs.
- Adding an agent = one new file exporting an `AgentDefinition` + one line in `registry.ts`. No engine changes.

## AI router (`src/lib/ai/`)

- Provider detection: explicit `AI_PROVIDER` → first present key → `mock`.
- Model tiers (`fast | balanced | premium`) resolve per-provider, overridable via `CREWOS_MODEL_*`.
- All adapters are plain `fetch` (no SDK lock-in) and return normalized `{text, tokensIn, tokensOut}`; estimates fall back to chars/4.
- **JSON robustness**: `extractJson()` strips fences and pulls the outermost object/array out of chatty prose; JSON-mode (`response_format` / `responseMimeType` / Ollama `format:"json"`) is requested when the agent asks for JSON.
- **Mock provider** parses the structured `TASK:` lines the engine embeds in prompts and returns deterministic plausible JSON — this is why the product is fully testable with zero keys (contract verified by `npm run smoke`).

## Queue (`src/lib/queue.ts`)

- Postgres-backed: `Job(status PENDING→RUNNING→DONE|FAILED, runAt, attempts)`, claimed in order, 3 attempts, 60s backoff.
- Why not Redis/BullMQ at launch: one less paid/free-tier-limited service; DB transactions give at-most-once claiming good enough for agent runs (idempotent by `AgentRun` status). **Upgrade path:** swap `claimJobs()` internals for Redis `BRPOPLPUSH`; the interface (`enqueueJob`, `processPendingJobs`) stays.

## Auth (`src/lib/auth/`)

- JWT session cookie (HS256 via `jose`, `httpOnly`, `SameSite=Lax`, `Secure` in prod, 30d).
- Identity paths converge in `ensureUserAndWorkspace()`: email magic link, Google/Microsoft OAuth (hand-rolled code flow, state-cookie CSRF check), and the env-gated demo login. First sign-in provisions workspace + OWNER membership.
- Every page under `/app` resolves session + membership in the layout; every API route resolves it again via `withWorkspace()` — **workspace-scoped queries everywhere** (no cross-tenant reads by construction).

## Billing (`src/lib/stripe.ts`, `api/webhooks/stripe/`)

- Checkout sessions carry `metadata {wsId, plan, annual}`; the webhook is the single source of truth for `Subscription` + `Workspace.plan`.
- Status mapping `active→ACTIVE … canceled→CANCELED`; cancellations downgrade the workspace to STARTER.
- First-paid-checkout → referral ledger credit ($100) for the referring workspace (code captured via 30-day cookie at signup).

## Security posture

- zod validation on every mutating route; role checks (`requireRole`) on billing/branding/invites.
- Stripe webhook: raw-body signature verification, 501 when unconfigured.
- Rate limits: AI runs 10/min/workspace, auth 8/min/IP (in-memory token bucket; pluggable for Redis).
- Security headers via `next.config.mjs` (CSP, XFO DENY, nosniff, referrer policy). Secrets server-only.
- Proposal HTML is generated by our template with `escapeHtml()` on every AI-produced string before storage.

## Deliberate deferrals (documented, not forgotten)

| Deferred | Why | Path |
|---|---|---|
| Real email *sending* of outreach | Compliance + deliverability work; queues/approvals are the wedge | Pluggable email adapter exists; add per-workspace SMTP/Resend + warmup guidance |
| Affiliate portal | Referral credits validate the loop first | `ReferralLedger` already models payouts |
| Redis/BullMQ | Free-tier constraint | Swap `claimJobs` |
| Multi-workspace switcher | Single-workspace users at launch | Session carries `wsId`; UI is one line |
| Usage hard-kill on overage | Hostile UX before product-market fit | 80%/100% banners + server-side limit on *new* runs |
